# ふたりの家計室 要件定義書

| 項目 | 内容 |
|---|---|
| 文書版 | 1.3 |
| 作成日 | 2026-08-15 |
| 対象 | 個人利用向け家計精算・将来支出シミュレーションWebアプリ |
| 本番想定 | Next.js / Vercel / Google Sheets API / DB不使用 |
| 文書状態 | 初期リリース要件確定案 |

## 1. 背景と目的

同棲中の2名が、Amexの共有利用分、家賃、固定費、他カード、その他の立替費用を月単位で集計し、精算金額を簡単かつ再現可能に算出する。

Amexは個人開発向けの自由な取引明細API利用が難しいため、会員サイトから出力したExcelまたはCSVを利用する。その他の支出はフォーム入力で補完する。また、現在の支出実績を起点とした1〜5年間の支出比較に加え、二人の収入・資産・住宅・教育・老後を最長50年間の月次キャッシュフローとして試算する。

## 2. プロダクト目標

- 月次精算の計算を10分以内に完了できること。
- 同じ明細ファイルと設定から、常に同じ請求金額を再計算できること。
- Amex明細の除外漏れ、H列優先漏れ、ETC漏れを防止すること。
- 実績データを変更せず、将来の支出前提だけを動かして比較できること。
- 個人の金融情報を、許可された本人以外から閲覧できないこと。

## 3. 利用者と権限

| 利用者 | 初期リリースでの権限 |
|---|---|
| 主利用者 | 明細取込、支出登録、計算、修正、シミュレーション、データ削除 |
| 同居パートナー | 共有パスワードでログインし、主利用者と同じ家計データを利用する |
| システム管理者 | 主利用者と同一。VercelとGoogle Sheetsの設定を管理する |

本番版はGoogleログインを使用しない。Vercel環境変数に保存したscryptハッシュと入力パスワードをサーバー側で照合し、成功時に署名済みセッションCookieを発行する。

## 4. 対象範囲

### 4.1 初期リリースに含むもの

- Amexの `.xlsx` / `.csv` 明細取込
- 指定ルールによる対象明細判定と合計
- 取込結果の確認および手動対象切替
- 家賃、固定費、その他費用の手入力
- 各手入力項目の請求割合設定
- 月次請求予定額の表示
- 毎月項目の管理
- 節約・基準・ゆとりの3シナリオ比較
- 1年、2年、3年、5年の支出予測
- 年間上昇率および一度だけの出費の設定
- 二人別の手取り、賞与、昇給、退職、年金の入力
- 現預金、投資残高、積立、期待利回りの予測
- 可処分手取り比例、50%ずつ、任意割合による共通費分担
- 一時費用と継続費を持つライフイベント
- 生活防衛資金判定と資金不足時期の検出
- 賃貸継続と住宅購入のコスト・持分比較
- 子どもの誕生時期・進路別の教育費概算
- 悲観・基準・楽観のライフプラン比較
- Google Sheetsへの月別状態の保存・読込
- 月次締めボタンによる前月データの確定保存
- 月次履歴による締め済み月の明細・内訳・合計確認
- 欲しいものリストによる購入候補の管理、カテゴリ別・全体合計の確認
- 管理者用パスワードで保護した個人資産エリア
- 自分の給料、口座残高、投資状況、月次個人支出の登録
- 残るお金、総資産、予備資金控除後の投資可能額、12か月の資産予測
- 共有パスワードによる本人限定アクセス

### 4.2 対象外

- Amexへの直接API接続
- 銀行口座、他社カード、家計簿サービスとの自動同期
- 振込、カード決済、請求書送信などの決済処理
- 税務・投資・保険に関する助言
- レシートOCR
- 複数世帯・組織向けのマルチテナント運用

## 5. 業務ルール

| ID | ルール |
|---|---|
| BR-001 | Amex明細の計算対象はExcel上の8行目以降とする。1〜7行目は基本情報として読み飛ばす |
| BR-002 | D列をNFKC正規化し、空白を整理したうえで大文字の `CHIHARU SATO` と完全一致する行を対象とする |
| BR-003 | C列に `ETC` を含む行は、D列の名義に関係なく対象とする |
| BR-004 | C列に「前回分口座振替金額」を含む行は、BR-002またはBR-003を満たしても必ず除外する。誤記対策として「前回分講座振替金額」も同様に扱う |
| BR-005 | H列が空欄でなければH列の金額を採用し、空欄の場合はF列を採用する。H列の0円は有効な値として優先する |
| BR-006 | マイナス金額は返金・取消として合計から減算する |
| BR-007 | Amex対象合計は、対象行の採用金額の総和とする |
| BR-008 | ETCは全額をAmex対象合計へ加える。ETCを50%按分する場合は、明細抽出ルールとは別の精算ルールとして設定する |
| BR-009 | 手入力請求額は `元の金額 × 請求割合 ÷ 100` を1円単位で四捨五入して求める |
| BR-010 | 月次請求予定額は `Amex対象合計 + 手入力請求額合計` とする |
| BR-011 | 画面の主表示は `月次請求予定額 ÷ 2` を一人あたりの請求予定額として1円単位で四捨五入する。二人分合計も補助表示する |
| BR-012 | 「毎月発生する費用」に設定された手入力項目だけを、将来シミュレーションの初期値へ反映する |
| BR-013 | シミュレーションは実績データを変更せず、保存操作をした場合だけシナリオとして保存する |
| BR-014 | 二人の同時更新をrevisionで検知し、古い画面からの上書きを拒否する |

### 5.1 計算例

- `CHIHARU SATO`、F列1,000円 → 1,000円を加算
- `CHIHARU SATO`、F列1,000円、H列800円 → 800円を加算
- `OTHER USER`、C列にETC、F列500円 → 500円を加算
- 「前回分口座振替金額」9,000円 → 0円として除外

Amex対象合計は2,300円。さらに家賃120,000円、請求割合50%を登録した場合、請求予定額は62,300円となる。

## 7. 画面要件

### 7.1 前月の精算画面

- 現在日の日本時間の前月を締め対象月として表示する。
- 最上部に一人あたりの請求予定額を大きく表示し、二人分合計と一人分のAmex・手入力内訳を補助表示する。
- ファイル選択直後に取込結果を表示し、保存前に確認できるようにする。
- 判定理由を「名義一致」「ETC共通」「前回振替・除外」「対象外」で区別する。
- H列採用時は「H列を採用」と明示する。
- 手入力費用は同一画面で追加できる。
- 「前月分を月次締め」ボタンで対象月と締め状態を確定する。

### 7.2 将来シミュレーション画面

- 節約・基準・ゆとりの各シナリオについて、最初の12か月の合計を並べて表示する。
- 前提値の変更を即時に結果へ反映する。
- 年別の棒グラフと直近12か月の金額を表示する。
- 一時支出が発生する月を視覚的に区別する。

### 7.3 ログイン画面

- 共有パスワードだけを入力し、Googleアカウントは要求しない。
- 認証失敗時にパスワード、ハッシュ、環境変数を表示しない。

### 7.4 ライフプラン画面

- カード精算額と世帯キャッシュフローを別データとして扱う旨を明示する。
- 悲観・基準・楽観の3シナリオについて期末純資産と資金不足有無を並べる。
- 入力項目は基本資産、二人の収入、生活費、運用、イベント、住宅、教育へ折りたたんで整理する。
- 初月収支、期末現預金、期末純資産、生活防衛可能月数を表示する。
- 年別の収入・支出・純資産と、直近月・イベント月・警告月の明細を表示する。
- 住宅比較では現金流出だけでなく、住宅価値からローン残高を引いた持分を表示する。

### 7.6 個人資産画面

- 共有パスワードに加えて、管理者用パスワードを入力した場合だけ表示する。
- 自分の月給、予備資金、口座残高、メイン口座、投資先ごとの評価額・評価損益率、個人支出を入力できる。
- メイン口座について、`口座全額 - (給料 + 請求額)` の「給料・請求額を除いた残高」を表示する。
- 選択月の請求額と共有費用は精算対象の月次状態・履歴から自動取得する。個人キャッシュフローのAmex引落額は、カード名義に関係なく前回振替行を除いた全明細から自動取得する。
- 残るお金、口座・投資を含む総資産、投資済み評価額を除き予備資金を残した投資可能額、インカム80%・キャピタル20%の配分を表示する。
- 予備資金は対象月に紐付かない手元資金の設定として、いつでも0円以上で変更できる。変更後は共通設定へ自動保存し、月を切り替えても同じ値を保持する。初回値は10万円とする。
- 投資状況は対象月に紐付かない共通設定として、投資先ごとの評価額・評価損益率を保存し、月を切り替えても同じ内容を引き継ぐ。
- 選択月の残るお金が毎月続く前提で、`将来月の総資産 = 現時点の総資産 + 残るお金 × 経過月数` として12か月の資産推移を表示する。給料・請求額の合計を別途毎月加算しない。月を切り替えた場合は、対象月の個人資産スナップショットを読み込む。

### 7.5 欲しいもの画面

- もの、カテゴリ、金額、URLを入力して登録できる。URLは任意とする。
- 全体合計、登録件数、カテゴリ数を上部に表示する。
- カテゴリごとの登録件数と金額合計を表示する。
- 登録一覧から商品ページを開き、不要な項目を削除できる。
- 登録内容は月次精算・月次締めとは独立して保持する。

## 8. データ要件

- 保存先は主利用者が所有するGoogle Spreadsheetとする。
- 生のExcelファイルは原則サーバーへ送信せず、ブラウザで解析した正規化済みデータのみを保存する。
- 明細には取込元行番号、元金額、採用金額、採用列、判定理由、手動変更有無を保持する。
- ライフプラン入力は精算台帳と分離した `lifePlan` 状態として保存し、計算結果は保存せず入力から再計算する。
- 金額は整数の日本円として扱う。
- 日時はISO 8601、システム表示はAsia/Tokyoを基準とする。
- 1つのSpreadsheetを1世帯専用として使用し、月ごとに `state_YYYY-MM` タブを分ける。
- 欲しいものリストは同じSpreadsheetの `wishlist` タブへ独立保存し、月次状態の切替・締め処理では削除しない。
- 個人資産は同じSpreadsheetの `personal_assets_YYYY-MM` タブへ月別保存し、予備資金は `personal_settings` タブへ共通設定として保存する。共有家計のAPI権限とは別に管理者セッションを要求する。旧 `personal_assets` タブは移行元として扱う。
- 精算対象月は現在日の日本時間の前月とする。月次締めボタン押下時に対象月の `state_YYYY-MM` タブへ締め済み状態を保存する。サーバー側の定期バッチは使用しない。

## 9. 非機能要件

| 分類 | 要件 |
|---|---|
| セキュリティ | ハッシュ化共有パスワードで認証し、Sheets認証情報をブラウザへ公開しない |
| プライバシー | 生ファイルの外部送信を行わず、ログへ氏名・明細・金額を出力しない |
| 性能 | 2,000行以内の明細を通常端末で3秒以内に解析し、条件変更から500ms以内に再描画する |
| 可用性 | VercelおよびGoogle Sheets APIの稼働範囲で提供する。障害時は端末内の未保存データを維持する |
| 操作性 | PCとスマートフォンで利用でき、主要操作はキーボードでも実行できる |
| アクセシビリティ | WCAG 2.2 AAを目標とし、ラベル、フォーカス表示、色以外の状態表現を提供する |
| 対応ブラウザ | 最新2世代のChrome、Safari、Edge。モバイルSafari、Chromeを含む |
| 保守性 | 計算ロジックをUI・Sheets通信から分離し、自動テスト可能にする |
| 監査性 | 自動判定、手動補正、保存日時、更新者を追跡できる |

## 10. 受入条件

1. 計算例のAmex対象合計が2,300円になる。
2. H列が0円の場合、F列に金額があっても0円を採用する。
3. 前回分口座振替金額は手動でも対象に変更できない。
4. ETCは名義不一致でも対象になる。
5. 家賃120,000円・請求割合50%が60,000円として加算される。
6. 実績反映後も元明細が変更されない。
7. 節約・基準・ゆとりの結果が同じ画面で比較できる。
8. 未認証状態ではAPIは401を返し、画面アクセスはログイン画面へ移動する。
9. Spreadsheetの権限を外した場合、機密情報を含まないエラーが表示される。
10. Vercel本番ビルドと計算テストが成功する。
11. 投資積立は現預金から投資への振替として扱い、積立だけで純資産が減らない。
12. 退職月以降は給与が停止し、年金開始月以降は年金が収入へ加算される。
13. 一時イベント費用は発生月に1回、継続費用は指定期間だけ加算される。
14. 住宅購入では元利均等返済を用い、住宅価値とローン残高を純資産へ反映する。
15. 現預金が最低残高を下回る前に投資積立を減額し、それでも不足する場合は投資を取り崩す。
16. 既存の保存データに `lifePlan` がなくても、初期値を補って読み込める。
